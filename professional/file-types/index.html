Purl's file types

Your data is yours. This page says how Purl's files are built, so you can read them with your own tools, convert them, or keep them safe without Purl.

Purl has no server. Everything you make lives on your device, and leaves it in one of these files:

ExtensionWhat it holdsInside
.purlA backup: everything, or what you ticked in Export & importA short binary header, a JSON manifest, then the raw files
.purlpOne shared pattern or chart, or a set of blueprintsPlain JSON (rename it to .json to read it)
.purltYour barcode templates, sharedPlain JSON

The .purl backup

A backup is one file in three parts. Nothing is zipped and nothing is base64 encoded, so a 600 MB pattern PDF takes 600 MB in the backup, and any tool can find the start of the manifest without unpacking anything.

BytesWhat
0 to 3The text PURL
4 to 7The format version, a 32 bit little endian number: 3
8 to 23The length of the manifest in bytes, written as 16 hexadecimal characters, for example 000000000001a2f4
24 onwardThe manifest: UTF-8 JSON, as long as the header says
After the manifestThe files, one after another, in the order the manifest lists them

The manifest

{
  "_purl": "purl-backup",
  "version": 3,
  "exportedAt": 1792008320092,
  "appVersion": "0.4.18",
  "data": {
    "purl:stash": "[{\"id\":\"y-1\",\"brand\":\"...\", ...}]",
    "purl:projects": "[...]",
    ...
  },
  "files": [
    { "uri": "file:///.../p1a2b3c4.pdf", "dir": "patterns", "size": 48211 },
    { "uri": "file:///.../ph5k6l7m.jpg", "dir": "photos", "size": 9180 },
    { "uri": "file:///.../cc-ring.json", "dir": "crochet-in", "size": 2044, "cc": { "id": "cc-ring" } }
  ]
}
  • exportedAt is the time of the backup in milliseconds since 1970. appVersion is the Purl version that wrote it; older backups may leave it out.
  • data holds Purl's saved records. Each key starts with purl:, and each value is itself a JSON text, so parse it a second time. purl:stash is your yarn, purl:projects your projects, purl:patterns and purl:userpatterns your patterns.
  • files lists the raw files. size is the length in bytes. A file's place in the backup is not stored: the first file starts right after the manifest, and each next file starts where the one before it ends. uri is where the file sat on the device that made the backup; a restore gives it a new place.
  • dir says what the file is: patterns (a pattern PDF), photos (a picture), crochet-in (a crochet chart), blueprints-in (a blueprint), studio-in (a Garment Studio garment) or sketchpad-in (one file of a Sketchpad sketch). Chart, blueprint, garment and sketch files are JSON.
  • Since October 2026 an entry for a chart, blueprint, garment or sketch may also carry its name and the time it was last edited (at), so a list can show it without opening the file.

Read one with Python

This script, with Python's standard library only, prints what a backup holds and can unpack it into a folder: the manifest, one JSON file per record list, and every raw file. Download read_purl.py.

python read_purl.py my-backup.purl            # summary
python read_purl.py my-backup.purl unpacked   # unpack into ./unpacked

The core of it is short enough to write in any language:

head = f.read(24)                       # b"PURL", version, 16 hex chars
version = struct.unpack("<I", head[4:8])[0]
manifest_len = int(head[8:24], 16)
manifest = json.loads(f.read(manifest_len))
offset = 24 + manifest_len
for entry in manifest["files"]:
    f.seek(offset); data = f.read(entry["size"])
    offset += entry["size"]
stash = json.loads(manifest["data"]["purl:stash"])

A sound backup ends exactly where its last file ends. If the file is shorter than the header, manifest and listed sizes add up to, the backup was cut short, for example by a copy that did not finish; Purl tells you so before you restore.

Older backups

Purl still reads two older kinds. A version 2 backup is text, one JSON object per line: a first line with "_purl": "purl-backup" and "version": 2, then a line per saved record ({"t":"kv","k":...,"v":...}), a line naming each file ({"t":"f","u":...,"d":...}) followed by its bytes in base64 lines ({"t":"c","b":...}) and {"t":"e"}, and {"t":"done"} at the end. A version 1 backup is one JSON object with data and the files in base64. Purl writes only version 3 today.

The .purlp shared file

When you share a pattern, a chart or blueprints, Purl writes one .purlp file. It is plain JSON. The first key, _purl, says which of the three it is:

_purlWhatMain fields
purl-patternA patternversion (2), pattern, and when they apply cover, photosLeft, crochet, knit
purl-chartA colour, knit or crochet chartversion (1), kind (colour, knit or crochet), chart
purl-blueprintBlueprints, saved parts of a chartversion (1), maker (the chart maker it was shared from), blueprints (a list)

A shared pattern

{
  "_purl": "purl-pattern",
  "version": 2,
  "pattern": { "title": "...", ... },
  "cover": { "data": "<base64>", "ext": "jpg" },
  "photosLeft": 2,
  "crochet": [ { "version": 1, "kind": "crochet", "chart": { ... } } ],
  "knit":    [ { "version": 1, "kind": "knit", "chart": { ... } } ]
}
  • pattern is the pattern as Purl stores it, without any path on the sender's device.
  • cover is the cover picture, base64 encoded, with its file type. It is left out when the pattern has none, or when it is too large (over 12 million base64 characters, about 9 MB).
  • photosLeft counts the pictures the sender had that the file does not carry.
  • crochet and knit are the pattern's own chart copies, each shaped like a shared chart without its _purl key.

A shared chart

{ "_purl": "purl-chart", "version": 1, "kind": "crochet", "chart": { ... } }

chart is the chart exactly as Purl stores it, so a field a newer Purl adds still travels. A crochet chart carries the drawings of the stitches its maker drew by hand (own), only those the chart uses; a built stitch needs nothing extra, since its name, such as tr.puff.6, is its definition. Importing a chart never overwrites one you have: it arrives as a new chart, and a name you already use gets a number, such as "Rose (2)".

A yarn record

Your stash is the list under purl:stash in a backup. Each yarn is one JSON object. Only id, skeins and createdAt are always there; every other field is left out when it is empty.

FieldTypeMeaning
idtextPurl's own id for the yarn
brand, nametextMaker and yarn name
colortextThe colour's name
colorHextextThe colour as #rrggbb
colorHexeslist of text2 to 10 colours for a striping or multicoloured yarn; the first is also in colorHex
dyeLottextDye lot
fiberslistThe blend, each { "name": "Alpaca", "percent": 100 }
fibertextThe blend as one line, kept for older readers
weighttextOne of Lace, Fingering, Sport, DK, Worsted, Aran, Bulky, Super Bulky, Other
skeinsnumberHow many skeins, halves allowed (3.5)
lengthPerSkeinnumberMetres per skein. Always stored in metres; Purl shows yards when you choose imperial units
gramsPerSkeinnumberGrams per skein, always stored in grams
needleSize, gaugetextKnitting needle and gauge from the ball band
crochetHook, crochetGaugetextHook and gauge for crochet
caretextWashing and care
barcodeslist of textBarcodes scanned for this yarn
pricePerSkeinnumberPrice per skein
storetextWhere you bought it
notestextYour notes
rebuytrueMarked to buy again
createdAtnumberWhen it was added, in milliseconds since 1970

  "id": "y-alpaca",
  "brand": "Example Yarns",
  "name": "Alpaca 4 ply",
  "color": "Light grey",
  "colorHex": "#bfbfbf",
  "weight": "Fingering",
  "skeins": 6,
  "lengthPerSkein": 167,
  "gramsPerSkein": 50,
  "fibers": [ { "name": "Alpaca", "percent": 100 } ],
  "createdAt": 1780304400000
}
